# Everyday English implementation plan

**Phase 0 · 2026-11-13 · Architecture direction provisionally supported. Phase 1 requires explicit approval.** The separately supplied `CODEX_ENGINEERING_SPEC_V1.md` defines the gates. This plan starts with one five-minute introduction exchange on the learner’s laptop. [Experience map](EXPERIENCE_TO_CODE_MAP.md) · [Tutor harness ADR](TUTOR_HARNESS_ADR.md) · [Baseline verification report](BASELINE_VERIFICATION.md)

## Product decisions carried into every phase

1. Show French and English instructional overlays from the beginning. Fade individual aids only after demonstrated independence for the relevant capability. Restore on request and honor accessibility preferences.
2. Give the learner time to think. Silence alone yields no error, confusion label, failed attempt or automatic progression.
3. Keep the learner camera off by default and request permission only on explicit action. Denial, revocation and absence leave general progression available. A camera-based activity needs an equivalent path.
4. Preserve the immersive, video-first tutor stage. Compare avatar technologies and fallback renderers before selection. A scripted preview can establish layout and interaction without deciding the production renderer.
5. Keep curriculum progression and authoritative learner memory under deterministic application control. The model can propose assistance and provisional observations through the bounded harness.

## Baseline and constraints

The existing repo has no WebRTC tutor, private identity, database, live avatar, frame interpretation or review policy. [Source and runtime scripts](../README.md) · [Server checks](../.github/workflows/ci.yml) · [Pages workflow](../.github/workflows/pages.yml)
- Preserve local browser progress, existing generic Pages behavior and safe cache scope until an approved migration. Set a feature boundary for the new experience and prove server and static export independently before private code lands. Server handlers requiring a runtime and auth cannot be compiled as a dynamic API into the Pages artifact. If an environment flag cannot maintain a clean boundary, use an explicit static-only demo entry/build from the same repository. Choose the smallest proven option in Phase 2. [Next.js export limits](https://nextjs.org/docs/app/guides/static-exports)
- Keep the approved first session bounded. Join and French welcome → Daniel models a greeting → ask a name question → learner responds → diagnose and repair if needed → transfer to an approved different voice/wording such as Maria → speak a qualified recap and commit. Retain a small, accessible meaning check and visible English/French in teaching. A learner who uses support can complete a worthwhile session. Evidence labels reflect cues and modality.

## Test design and first real-slice gate

| Layer | Required coverage |
| --- | --- |
| Pure policy and fixtures | Transition table for accepted and invalid transitions. Fake clock for pause, delayed review and lease. Old epoch/turn/output events, out-of-order and duplicate messages, wrong activity/revision, render aid exposure, restored aid, audio missing, malformed/out-of-policy proposals, unassessed silence, unrelated reply and legacy migration. No device event or model utterance can award mastery. |
| Persistence and provider integration | Real test PostgreSQL with transaction rollback, uncertain commit/retry, version pinning and revision checks. Fake provider for timeout/error/dedup/hangup. Redacted logs, limited data in a real export, restore and deletion. Reserve only one provider session per learner and reconcile ambiguous calls. A failed/expired call must never reopen devices. |
| Browser and accessibility | Playwright for server and Pages paths. Deterministic event script, keyboard-only and focus order, single-select repair, no auto consent, consent revoked, mic/camera denied, captions and French help, replay/slow, hidden tab, offline fallback, reconnect and resume, export/delete. Screenshot comparisons at both laptop sizes. Manual screen-reader announcements and zoom/reflow with reduced motion and high-contrast settings. |
| Realtime and pedagogy | On target hardware measure actual playback readiness, end-of-turn to first audio, barge-in stop delay and frequency of false cutoffs, turn quality in both languages, usable captions, provider spending and safe failure. Provisional engineering targets for review are tutor audio within two seconds on at least eight of ten clean test turns and clearly responsive cancellation with no stale caption/output. Record outliers and compare fallback. Evaluate comprehension separately from reading, supported production separately from independent transfer, and repeat success separately from later retention. |

Phase 3 is done when the learner can start privately, hear a short welcome, respond by speech with French support, interrupt, receive useful repair, attempt a varied exchange, resume after interruption and see a recap backed by distinct persisted evidence. A failed device or an uncertain transcript yields a safe fallback and no false failure. The app uses accurate labels for audio, camera, avatar and save state. Real retention and independent skill advancement remain Phase 4/5 observations.

## Open decisions and risks

| Decision or risk | Recommendation, dependency and owner |
| --- | --- |
| Bilingual defaults and caption legibility | Confirm placement for French meaning in the refined listening/response states, difference between captions and French help, wrapping, pause control and camera-off variant. Product owner/design director before Phase 1. |
| Tutor presence and representation | Approve asset rights, Daniel’s identity, crop and truthful preview labeling before Phase 1. The production stage stays video-first. Evaluate a still fallback, locally animated character and live avatar on the same stage. Compare presence, audio/video sync, interruption, accessibility, processor terms and cost before selecting production technology. Product owner/design director. |
| Listening versus reading and transfer | Approve a fresh transfer variant and whether a brief opt-in probe may reduce specific cues. Track exposed aids either way. Agree on appropriate rubric, modalities and delayed-review interval before Phase 4. Product owner/design director, with a qualified reviewer for calibration. |
| Natural endpointing and barge-in | Echo and hesitant speech can cause false cutoff. Set conservative detection and protect the learner’s turn, then test with actual speakers/headset. Keep an accessible manual stop/talk/continue path. Engineering verifies at Phase 3 before learner activation. |
| Auth, provider costs and retention | Choose learner-friendly sign-in, runtime/DB and acceptable fixed costs before Phase 2. Confirm actual per-session budget, enforcement after network/server failure, acceptable vendor retention and whether provider tracing is disabled before Phase 3. Product owner approves, engineering proves controls. |
| Resume semantics and data migration | Agree what counts as saved and how to disclose a lost in-flight turn. Decide whether to import old browser progress. Keep original intact and provisional. Lock details before Phase 2. |
| Multimodal scope | A curated context image is available without camera upload. Live frame analysis requires a separate meaningful task, consent/cancellation and equivalent voice/text/click path. Do not equate Figma’s pointing example with a committed capability. Product owner at Phase 4. |
| Deployment drift and PWA updates | Prove that Pages remains generic and private responses stay uncached. Version public assets and swap/update at a safe checkpoint. Validate on the learner’s browser and installed shell, with rollback and logout tested before pilot. Engineering in Phases 2 and 5. |
